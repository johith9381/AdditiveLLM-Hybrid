1. ISSUE SUMMARY & REPORTED BUG
----------------------------------------------------------------------------------------
- Problem: Entering "what is the material used" into Prompt mode previously produced a
  confident defect prediction (None: 87.2%, Keyhole: 1.7%, LoF: 8.6%, Balling: 0.1%)
  with colored probability bars and an easily overlooked "LOW" badge.
- Violation: Section 5 requires that queries containing NO extractable process parameters
  (bare questions or meta-tool queries) MUST be classified as off-domain or in-domain-partial,
  triggering clear rejection or clarification, and NEVER producing defect predictions.

2. ROOT CAUSE IDENTIFICATION
----------------------------------------------------------------------------------------
Two interlocking issues caused this defect leakage:
a) Frontend Payload Leakage (website/frontend/app.js):
   When submitting from "Natural Language Prompt" mode, the client script bundled the text
   query along with the current slider values (power=200, velocity=1000, etc.).
b) Backend Default Fallthrough (website/backend.py):
   Pydantic's PredictRequest schema defined default values (power=200.0, velocity=1000.0).
   The condition `if raw_text and (p is None or v is None)` evaluated to False, bypassing
   Stage 1 open-domain parsing entirely. Furthermore, backend.py lacked strict category
   guardrails to abort inference when a query was classified as 'off-domain' or
   'in-domain-partial'.

3. IMPLEMENTED ARCHITECTURAL FIXES
----------------------------------------------------------------------------------------
a) src/open_domain_extractor.py:
   - Parameter Counting: If num_extracted == 0, query is strictly classified as 'off-domain'
     with an explicit rejection message explaining required L-PBF build parameters.
   - Regex Disambiguation: Refined beam diameter, hatch spacing, and layer thickness regexes
     to require explicit physical keywords ("beam", "hatch", "layer/thickness"), preventing
     generic unit strings (e.g., "30 microns") from falsely satisfying multiple parameters.
   - Benchmark Suite Expansion: Expanded benchmark from 40 to 58 queries, incorporating
     18 adversarial queries (bare questions, meta-tool queries, single words: "titanium",
     "fast", "1000", "defect", "porosity"). Classification accuracy: 100.00% (58/58).

b) website/backend.py:
   - PredictRequest updated: added explicit `mode` parameter ("manual", "prompt", "baseline")
     and removed default numerical values (default None) to prevent spoofing.
   - Strict Stage 1 Router:
     * If mode == "prompt": parse_query_two_stage(raw_text) is ALWAYS executed.
     * If category == "off-domain": returns HTTP 200 with status="rejected", message, and
       all missing fields. Stage 2 inference is completely skipped (0 forward passes).
     * If category == "in-domain-partial": returns HTTP 200 with status="clarification_needed"
       and exact missing fields. Stage 2 inference is completely skipped.
     * If category == "in-domain-complete": extracted values are passed to Stage 2 inference,
       and physical boundaries are verified for extrapolation.

c) website/frontend (index.html, style.css, app.js):
   - app.js: In prompt mode, only the raw prompt text and mode="prompt" are transmitted.
   - app.js: If response status is "rejected" or "clarification_needed", defect probability
     bars, physics aspect ratios, and gating weights are completely HIDDEN.
   - index.html & style.css: Added a prominent alert card (#clarificationAlert) with red/amber
     styling, explicit error heading, descriptive message, and individual badges for missing
     parameters.
   - Regime Banner: Dynamically switches to "REJECTED" (red) or "PARTIAL" (amber) instead of
     displaying confident "LOW RISK" defect banners.

Reproduction Overview & Methodological Findings

Comparative summary between published claims and empirical implementation reality.

Reproduction Scope & Verification

This reproduction implements the exact multi-label defect classification over four non-mutually-exclusive regimes: None (Desirable), Keyhole Porosity, Lack of Fusion (LoF), and Balling.

  • Evaluated all 4 architectures: DistilBERT (66M), SciBERT (110M), T5-Small (60M), Llama-3.2-1B (1.24B).
  • Loaded published RTX A6000 checkpoints under the official ppak10 Hugging Face namespace.
  • Evaluated both Baseline (parameter-ordered [SEP] syntax) and Prompt (natural language) formats.
  • Generated all tables (1, 2, 4) and figures (5–12) strictly from computed evaluation results.

Key Methodological Audit Findings

Our independent code and dataset audit uncovered two critical discrepancies in the published paper:

  • Frozen LLM Weights: The paper claims models were trained jointly with unfrozen weights. The author's code hardcodes freeze_weights=True and wraps forward passes in torch.no_grad(). Only a 16 KB linear head was trained.
  • Augmentation Leakage: Sweeping 400 hatch spacing & layer height combinations per base sample was performed before a random 75/15/10 split, causing near-total cross-split leakage of identical base melt pools into the validation set.

AUDIT 1 — Frozen-Weights Discrepancy Analysis

Discrepancy identified between paper Section 2.4 claims and author's actual code implementation.

Published Paper Claim (Section 2.4)

"In each case the weights of the LLM model remain unfrozen and were trained along with the classification head for up to 25 epochs for Baseline fine-tuning and 2 epochs for Prompt fine-tuning."

— Pak & Farimani (2025), Additive Manufacturing Letters 14, 100292

Actual Repository Code (model/llama.py)

# Model with frozen LLaMA weights class LlamaClassificationModel(nn.Module): def __init__(self, model_path = "meta-llama/Llama-3.2-1B", freeze_weights = True): super(LlamaClassificationModel, self).__init__() self.base_model = AutoModel.from_pretrained(model_path) if freeze_weights: for param in self.base_model.parameters(): param.requires_grad = False def forward(self, input_ids, attention_mask, labels=None): with torch.no_grad(): # No gradients for the base model outputs = self.base_model(input_ids=input_ids, attention_mask=attention_mask)

Checkpoint Payload Verification

Direct examination of all Hugging Face checkpoint repositories (ppak10/defect-classification-*) confirms that:
1. The only file updated and trained across checkpoints is classification_head.pt (~16 KB), which stores only the weights and biases of a single linear projection matrix ([hidden_size, 4]).
2. The base transformer weights (model.safetensors) are identical bit-for-bit to stock pre-trained weights from Meta, Google, and AllenAI.
3. Because with torch.no_grad(): is hardcoded in the forward pass, gradients were never computed or backpropagated into the LLM layers.
4. Therefore, the models were evaluated as frozen linear probes, not fine-tuned LLMs.

Schema Audit & Technical Details

As verified in the dataset schema, columns melt_pool_width and melt_pool_depth are absent from published baseline splits (which provide only id, label, and text).
Sibling groups were identified by parsing the 4 invariant physical parameters from the text field: (material, power, velocity, beam_diameter).
Because the paper performed the $20 \times 20$ Lack-of-Fusion sweep before applying df.sample(frac=0.75), each base measurement was fractured across train and validation splits.
The model was thus tested on nearly identical replicas of training examples with identical Keyhole and Balling labels, explaining why a simple frozen linear head achieved >93% accuracy.
